## What the traces show

The treatment sessions contain the expanded skill and the explicit subsequent
approval message. Both first exchanges visibly asked for approval and left source
and original tests byte-identical to the fixture. Raw tool starts show no
transient implementation/test edits before that request.

Qwen did not read the template. Its first written brief contained confused emoji
arithmetic, corrected in a second write before the visible approval request.
The final brief's examples agreed with TASK.md, but lacked full source tracing
and explicit stop conditions. Gemma read the template after recovering from an
incorrect relative path; its acceptance table was generic. Neither treatment
updated its brief with final evidence, leaving it less useful for resumption.

Both treatments changed production code before adding/running the new tests.
Initial passing tests covered only the unchanged countCodePoints API. Qwen later
corrected a new test that expected truncation for two emoji fitting a two-point
budget; it changed the input to three emoji and disclosed that correction. This
agrees with the original contract, but is not red-first evidence. Baseline Qwen
also corrected three newly introduced off-by-one test expectations. None of
these corrections removed an original regression assertion.

Gemma baseline separately invoked `echo $?` after its test tool call; that fresh
shell does not establish the previous command's exit status. Its actual test
tool succeeded and retained log showed 10/10, which support the handoff instead.

## Verification and limits

Before the live calls, the primary reviewed the contract/checks and ran the
oracle against the stub, correct reference, and two deliberate mutants: the stub
failed 9 of 10, the reference passed 10, UTF-16 slicing failed 3 assertions, and
an ellipsis outside the budget failed 4. The later [retained validation](../runs/002-label-truncation/validation-mto86c53-2-3f88536302-QkO4oR/manifest.json)
reproduced these outcomes and the original five passing fixture tests. An earlier
validator setup attempt failed before child execution because of a missing
import; it remains retained, not counted as a model attempt.

Primary inspection found each generated module pure. Independent verification
used the frozen acceptance source and a separate copy of the original five
regressions, clean environment without provider credentials, Node permissions,
and a 20-second bound. The [verifier](../lib/verify-workflow.mjs) checks candidate
and oracle hashes and records actual command output/status. Qwen baseline used
the initial verifier before its compact refactor/self-snapshot addition; its
result retains command and checked-input provenance, not verifier-source
provenance. Later results retain that source too. No participant tests were
trusted as the independent oracle.

Effective sampling/thinking, proxy retries, response-cache freshness, and token
usage remain UNKNOWN. One uncontrolled attempt per arm does not establish
causality, reliability, or exhaustive correctness. The preservation candidate is
not part of this comparison; it is tested separately on the inventory task.

## Decision

The evidence supports continuing a small, user-visible skill experiment, not
building a new product harness. Approval visibility is currently the clearest
observed distinction. Red-first behavior and durable handoff evidence are open
instruction-following gaps. Keep them separate from code correctness, and test
any next instruction change in isolation instead of adding several rules at once.
