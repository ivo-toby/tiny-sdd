store. Fixed artifacts prepared by the primary; models consume the same packet
and starting code. This is not an evaluation of model-generated specifications.

Each gets a fresh fixture, fresh session and one 300000ms/40-tool call. One
revision is allowed, with the same budget and a fresh worker session on its
candidate, using feedback generated by the following fixed rule: include actual
failed check names/errors and primary review's exact violated contract clauses;
do not provide implementation code. No model fallback or undeclared retries.

Use product CLI when ready, record its version/file hashes, prompts, task/config
digests, raw events, snapshots and result. A runner defect invalidates that
execution for model comparison; retain it as development evidence and allow one
explicitly labeled runner-repair rerun on the original fixture. Do not alter
task expectations after seeing participant results.

Worker is edit-only. Primary executes candidate tests and held-out checks with
no credentials or external network, in a disposable verifier. Original fixture
regressions must stay byte-identical. Hold-out checks are absent from candidate
workspace and prompts. Before participants, establish that original regressions
pass, new checks fail for missing behavior, and a separately built reference
passes. Plausible defective references should be rejected by the checks.

Score behavior, prohibited changes and test quality before latency. Report all
attempts, timeout/upstream errors, tokens when exposed, tool calls and human/
strong-model preparation/review separately. No rank, reliability claim, prompt
causality claim, or fair weight/quantization comparison follows from one task.
Profile development used a different podcast task, but this is still a small
engineering transfer probe, not independent statistical validation.
